# Old-family mixed proof byte gate

No checked-in proof-byte baseline existed before arithmetic-fed chip inputs.
The old one-to-eight-call family is generated by `source_pinned_general.py`;
its printed receipt contains the exact proof length and SHA-256 for every
call count. The engine gitlink is `7d544c6839497ca19b6c7ef9b982e464f10cfeed`
in both the last pre-extension S31 commit
`96a95c6cbe266fd54f6a3ab57c7c314ea013a709` and the extension commit
`618cc4b9d7eb16f5b845c8c0c09ed2c488043ab4`.

After the paired cost timing run, make two clean, sequential baseline runs and
one candidate run using the same Zig compiler, platform and build flags. The
acceptance script already uses `ReleaseFast` and a separate temporary build
prefix per call count. Start from clean worktrees at the two commits above,
initialize the pinned `deps/stwo-zig` submodule, then run:

```sh
python3 src/frontends/s31/tests/acceptance/mixed_boundary/source_pinned_general.py > baseline-first.json
python3 src/frontends/s31/tests/acceptance/mixed_boundary/source_pinned_general.py > baseline-repeat.json
```

Run those two commands in the **pre-extension** worktree. Run the same command
once in the candidate worktree and write `candidate.json`. Record `zig version`,
`git rev-parse HEAD`, the engine gitlink, and the SHA-256 of the three JSON
receipts with the result. Then run this pure receipt gate from the candidate
worktree:

```sh
python3 src/frontends/s31/tests/acceptance/mixed_boundary/proof_byte_regression.py \
  /path/to/baseline-first.json /path/to/baseline-repeat.json /path/to/candidate.json
```

The repeated baseline is mandatory: it detects nondeterministic proof bytes.
The gate requires all eight proof lengths and hashes to match. Freeze the
validated baseline receipt with its source/toolchain provenance before making
this a CI compatibility check; do not silently refresh a mismatch. Until then,
proof-byte compatibility is an unrun release gate, not an established result.

# Independent review: general record statement model

Scope: `fe7fb40` (`RecordStatementV2.lean`, its 13-layout generated corpus,
and `general_statement_refinement_v2.py`), compared with the production Zig
`record_abi.zig`, `relation.zig`, and Python `abi/binding_v2.py`. This is a
source review and bounded fixture check, not an end-to-end verifier theorem.

## Findings

No concrete statement-parser bypass was found in the reviewed path. After a
relation and its ABI descriptor pass validation, the model and the two
implementations impose the same relevant claim conditions:

| Condition | Lean model | Zig / Python implementation |
| --- | --- | --- |
| Public leaves only, in declaration order | Supplied descriptor list; `checkOrdered` compares one claim per descriptor | Walks public input roots, then result leaves; skips private input roots; rejects different counts and paths |
| Word shape | Exact declared width and `< 2^31-1` for M31 or `< 2` for bit | `checkClaim` / `decode_public_statement` check integer type, nonnegative range, and exact length |
| Aliases | Every pair with the same `Fin n` wire carries equal words | First wire value stored in a map; later occurrences must equal it |
| Proof words | Public input wires, then distinct result wires, then zero padding to eight | Relation input and `public_outputs` order; ABI validation requires distinct result wire order to equal the relation; rejects empty or over-eight projections |

In particular, the generated `pair_4` case has three *named* four-word leaves,
but only one result wire. Its proof vector has eight words, not twelve. The
`private_1` and `private_2` cases omit the private root from both claims and
proof input words; they still claim computed public results. A changed alias
must change every occurrence, and the resulting vector changes. These are
useful nonvacuity checks of the model's first-occurrence projection.

The apparent eight-word admission difference is closed by the caller:
`record_abi.validate` itself does not count projected words, but
`relation.Program.validate` counts every public input and distinct declared
public output before calling it, rejecting zero or more than eight. Python
`validate_binding` performs the equivalent gate internally. Native
`claimedWords` also checks the bound while filling its eight slots. Thus this
does not admit an oversized validated program through the production entry.

## Exact proof boundary

The Lean theorem is conditional on descriptors already validated against the
relation, plus the public input/result wire lists. Its `Descriptor` structure
does not itself enforce a one-word bit, a unique source path, or a matching
relation wire shape. For example, a `.bit` descriptor with width two and the
claim `[0,1]` would pass `checkClaim` in the abstract model; both production
ABI validators reject that *descriptor*. Likewise, the model permits a wire
list supplied in the wrong order; it proves projection of the supplied list,
while the production validator must establish that the list is the relation's
order. These are explicit refinement premises, not native bypasses.

The generated corpus checks 13 compiled S31 layouts against the Python ABI
decoder and an independent Python tree walk, then kernel-checks Lean examples:
13 accepted claims, 13 accepted consistent changes, and 65 malformed
rejections. It does **not** invoke Zig for those 13 layouts. Its compiled
descriptor and Lean fixture share the same source compiler, so a compiler bug
which changes both in the same way may escape this check. Separate native
acceptance covers one nested layout and its malformed/changed-statement
corpus, not all 13. None of these checks proves canonical JSON or digest
agreement for every input, compiler-to-descriptor correspondence for every
source, private-input confidentiality, or STARK proof soundness.

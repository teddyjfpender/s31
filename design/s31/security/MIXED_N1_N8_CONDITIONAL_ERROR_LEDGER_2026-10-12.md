# Conditional error ledger for the source-pinned mixed N1–N8 profile

**Scope.** This is a source audit of the source-embedded `general_package` verifier and pinned `02bc8b3e8d28c7ef871192f36dfc5d18fb2f55d3` stwo-zig engine. It is an error-budget *ledger*, not a claimed security level. No native proof run was needed for the original arithmetic ledger. It applies to the admitted direct Gate + pair/many chip/bridge roster (`1 + 2N` components, `1 <= N <= 8`), not all S31 programs. The pin update binds the exported proof root vector to verifier-committed roots and rejects surplus zero-fold FRI layers; neither change supplies a whole-proof soundness theorem.

## Verified protocol settings and transcript order

[`direct_many_preflight.fixedPcs`](../../../deps/stwo-zig/src/integrations/circuit_cpu/direct_many_preflight.zig) constructs `FriConfigV2.init(26, 0, 1, 70, 1)`: **26 PCS/FRI PoW bits, last-layer log-degree bound 0, log blowup 1 (factor 2), 70 raw queries, fold step 1**. The preprocessed tree height is the circuit log size plus 1; other trees use the largest selected circuit/chip log size plus 1. [`direct_mixed_schedule.inspect`](../../../deps/stwo-zig/src/integrations/circuit_cpu/direct_mixed_schedule.zig) uses that function, checks live component geometry, and carries the PCS object into the selected source schedule. The S31 [`general_package` verifier](../../../src/frontends/s31/runtime/mixed_boundary/general_package.zig) reconstructs the source schedule before proof allocation, preflights the encoded proof against those exact parameters, and passes it to the native verifier. The native verifier rejects a different PCS config and a different preprocessed root.

The native [`direct_mixed_general_arithmetic` prover/verifier](../../../deps/stwo-zig/src/integrations/circuit_cpu/direct_mixed_general_arithmetic.zig) uses the `proving_5a7c5ed.Blake2sM31MerkleChannel` profile. Both transcript paths mix, in order: profile tag and source/manifest digest and call plan; channel salt; FRI config; preprocessed root; circuit identity; eight canonical public words; main root; a separately verified **20-bit interaction nonce**; then draw `z, alpha`; mix ordered claimed sums; commit interaction root; then composition/OODS and PCS/FRI. The lookup challenge follows the main commitment and 20-bit nonce. The PCS verifier mixes the 26-bit valid nonce **before** drawing FRI query positions ([`core/pcs/verifier.zig`](../../../deps/stwo-zig/src/core/pcs/verifier.zig)). [`FriConfigV2.mixInto`](../../../deps/stwo-zig/src/core/pcs/config_v2.zig) absorbs the five fixed parameters as two felts. The source/manifest digest and circuit identity have distinct SHA-256 prefixes. The profile tag is distinct from the fixed N3/N4 mixed profiles.

The [BLAKE2s M31 channel](../../../deps/stwo-zig/src/core/channel/blake2s.zig) rejects any sampled 32-bit limb `>= 2p` and reduces each remaining limb modulo `p=2^31-1`; under ideal independent hash output this makes each QM31 limb uniform. The [query sampler](../../../deps/stwo-zig/src/core/queries.zig) takes 70 masked 32-bit draws **with replacement**; [`Queries.init`](../../../deps/stwo-zig/src/core/queries.zig) sorts and deduplicates them for Merkle openings. Seventy is a draw count, not a promise of 70 distinct positions. [`FriConfigV2.securityBits()`](../../../deps/stwo-zig/src/core/pcs/config_v2.zig) computes `26 + 1*70 = 96`; that method is parameter arithmetic, not a theorem proving this profile has 96-bit soundness.

## Ledger

Let `q=(2^31-1)^4=21267647892944572736998860269687930881`. Let `Q_L` count all distinct **valid** post-main-commitment nonce/transcript continuations whose `(z,alpha)` an attacker tests, across all attempted main commitments. Each attempt must fix its tuple multiset before its own challenge draw. A separate resource bound or random-oracle argument must bound `Q_L`; the verifier accepts any valid nonce. Let `ε_AIR`, `ε_OODS`, `ε_FRI`, `ε_Merkle`, and `ε_FS` denote the as-yet unproved errors of the corresponding exact implementations and computational model.

| Term | Exact local setting or conditional bound | What remains to prove |
| --- | --- | --- |
| Lookup compression and denominator zeros | The checked [`lookup_budget`](../../../src/frontends/s31/runtime/mixed_boundary/lookup_budget.zig) caps `E <= 722185` tuple occurrences, integerized total absolute weight `B <= 12585504 < p`, and tuple degree `d <= 6`. Under one fixed pre-challenge multiset, injective tagged tuple encoding, correct AIR fraction equations, and independent uniform `(z,alpha)`, the [direct polynomial argument](LOOKUP_COMPRESSION_BUDGET_2026-10-11.md) gives `(7E-6)/q <= 5055289/q < 2^-101.73`. For `Q_L` attacker-tested valid continuations, the elementary union bound is `min(1, Q_L*5055289/q)`, before the other terms. | Bind every emitted tuple and multiplicity to the committed main/fixed columns and checked source roster; account for adaptively tested nonces and Fiat–Shamir queries. The registry's relation-layout declarations need a compiler/AIR correspondence proof. |
| Zero denominators | **Already included** in the preceding `7E-6` numerator as `E/q`; do not add it again. The honest [`logup_columns` writer](../../../deps/stwo-zig/src/prover/air/logup_columns.zig) returns `DegenerateDenominator` on zero before inversion. | Honest-prover rejection does not itself constrain a malicious interaction trace. The lookup argument treats any sampled zero denominator as a bad event; accepted AIR/PCS soundness must ensure the fraction equations are the ones committed. |
| AIR composition and OODS | The native verifier draws composition randomness after interaction commitment and an OODS seed after composition commitment ([`core/verifier.zig`](../../../deps/stwo-zig/src/core/verifier.zig)). Live handles supply degree and mask geometry. | A quantitative bound for false AIR constraints under this exact random combination, quotient, circle-domain/OODS sampling and lifted geometry is **not derived here**. Record `ε_AIR+ε_OODS`, without inventing a number. |
| FRI queries and PCS | Blowup 2, 70 raw draws, fold step 1, last-layer degree bound `2^0=1` (constant final polynomial). The [`core/fri` verifier](../../../deps/stwo-zig/src/core/fri.zig) derives the layer schedule and raw queries; PCS verifies Merkle openings. | A profile-specific FRI/DEEP/PCS theorem accounting for query reuse, composition degree, adaptivity, and the two lifted tree heights is **not present**. Record `ε_FRI+ε_Merkle`, not `2^-70`, `2^-96`, or the sum of PoW bits. |
| PoW and Fiat–Shamir | The 20-bit nonce precedes lookup draws; the 26-bit nonce precedes FRI queries. Both are checked and mixed. The [channel PoW code](../../../deps/stwo-zig/src/core/channel/blake2s.zig) verifies the predicate; accepted nonce choice is unrestricted. | PoW is computational work, not a standalone probability of false proof. A bound needs an adversary time/hash-query budget and a model of repeated valid nonce trials, transcript/commitment hashing, and domain separation. Record `ε_FS(A)` for a stated adversary budget `A`; none is fixed here. |
| Transcript domains | The mixed profile has a distinct initial tag, prefixed SHA-256 source/manifest and identity hashes, a fixed order of typed values, and an ordered [`TranscriptOrder`](../../../deps/stwo-zig/src/integrations/circuit_cpu/private_many_boundary.zig) check. [`Blake2sChannel.mixFelts`/`mixU32s`](../../../deps/stwo-zig/src/core/channel/blake2s.zig) hash the previous state with raw bytes, without a per-call type or length tag. | Prove that the admitted fixed-arity schedule has no ambiguous transcript encodings or cross-profile alias, then justify the chosen hash/random-oracle model. A variable-length future profile must not inherit this argument automatically. No independent numeric domain-separation term is established. |

The desired whole-verifier statement is consequently of the form `Pr[false acceptance] <= min(1,Q_L*5055289/q) + ε_AIR + ε_OODS + ε_FRI + ε_Merkle + ε_FS(A)` **only after** an accepted-proof-to-committed-AIR/lookup reduction establishes these events cover all false admissions. No such complete reduction or numeric bounds for the remaining symbols are in this audit. The lookup term is conditional algebra on a fixed tuple multiset; it is not a whole-proof security claim. Repeated prover attempts and selected valid nonces are why neither 20 nor 26 PoW bits may be simply added to `-log2` of the lookup term.

## Reproducible arithmetic and source checks

The 1–8-call [`lookup_budget.evaluate`](../../../src/frontends/s31/runtime/mixed_boundary/lookup_budget.zig) checks `R <= 2^16`, total chip rounds `S <= 2^18`, exactly nine output addresses, and `N <= 8`. Its maxima give `E=3R+2S+160N+9=722185`, `B=16(4R+8N+18+2S)+160N=12585504`, and `7E-6=5055289`. A direct independent Python calculation:

```sh
python3 - <<'PY'
from math import log2
p = 2**31 - 1
R, S, N, O = 2**16, 2**18, 8, 9
E = 3*R + 2*S + 160*N + O
B = 16*(4*R + 8*N + 2*O + 2*S) + 160*N
print(E, B, 7*E-6, log2(p**4/(7*E-6)))
PY
```

Output: `722185 12585504 5055289 101.73063785772997`. This check does not run a prover or verify the soundness premises.

Focused existing check: `zig test src/frontends/s31/runtime/mixed_boundary/lookup_budget.zig -O ReleaseSafe` passed all three tests, including N1/N8 envelope arithmetic, invalid geometry, and characteristic/overflow rejection.

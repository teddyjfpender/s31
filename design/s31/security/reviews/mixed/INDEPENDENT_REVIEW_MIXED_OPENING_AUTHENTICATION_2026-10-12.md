**Reviewed revision:** `9865b04` plus the ordered-log and tail-column checks in this review. The focused `test-mixed-opening-authentication` step passed with the repository's checked-out `stwo-zig` dependency after the tail-column extension. This is a regression check for one honestly generated, source-pinned, three-call private proof, not a proof of PCS or full S31 soundness.

The test first proves and accepts the unchanged envelope. Its explicit header length equals `general_package.headerLen(7)`, and the postcard decoder consumes the entire remaining proof. The inspected native geometry has seven slots. The closed registry assigns circuit slot 0, pair chip/bridge slots 1–4, and many chip/bridge slots 5–6; the test checks the circuit, first pair, and many kind tags and uses the source-derived `main_offset` and `interaction_offset` for every slot. It checks the decoded column counts against the live tree widths and requires a nonempty queried-value column before each mutation.

Each of 30 cases changes one decoded `M31` queried value by adding one: the first and last fixed-tree columns, then the first and last main columns of each slot, then the first and last interaction columns of each slot. It serializes the same proof object with the original envelope prefix, requires equal length and different bytes, and runs the production postcard shape preflight with the same inspected PCS parameters as `general_package.verifySourceBoundWithWitness`. The source-bound native verifier must then return `RootMismatch`. The custom runner requires the root-mismatch log's tree numbers in the exact mutation order: two `0`s, fourteen `1`s, fourteen `2`s. Four more cases change one authentication-path sibling in each commitment tree. It rejects unexpected error logs and requires 34 matching root-mismatch logs overall. The first/last check catches a component span whose prefix authenticates while its tail is omitted; the ordered-log check rejects a failure attributed to the wrong tree.

The native lifted Merkle verifier hashes the decoded queried values into leaves and compares the reconstructed root with the accepted commitment; the PCS layer reports the failing tree. Since the unchanged proof passes, the mutation is to a queried value, and the rewritten proof passes preflight, the observed `RootMismatch` is a substantive authenticated-opening rejection rather than a malformed-envelope or parser rejection. The test samples one query value in the first and last column of each slot. Slot attribution comes from the source-derived column offsets; Merkle authentication and the native error are **per tree**, not per component. The test does not check interior columns, every query, unopened rows, arbitrary prover proofs, or independent PCS/FRI/LogUp soundness.

**Verdict:** no blocker for the stated sampled-opening regression after the ordered-log fix. Preserve the narrower wording above when discussing the private boundary; acceptance-to-full-trace correspondence remains separate work.

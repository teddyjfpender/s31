# Independent public direct-Gate main-root review — 2026-10-12

**Scope:** the in-progress `inspect-physical-root` diagnostic for a transparent public M31×4 direct-Gate source. It shares the early source/assignment guard with `inspect-physical-rows` and returns a main commitment root plus SHA-256 of the 12×512 `writeBase` M31 words in column-major little-endian u32 order. This is an honest-prover correspondence check, not a general opening theorem.

I traced the [recommitment helper](../../../../../src/frontends/s31/runtime/public_main_commitment.zig) against the [direct prover](../../../../../deps/stwo-zig/src/integrations/circuit_cpu/direct_arithmetic.zig): both use the same `directPcsConfig`, install the preprocessed commitment as tree 0, then commit the 12 base columns as tree 1 with the same PCS engine. The revision's lifting height depends on tree index, so installing tree 0 first is necessary. The Merkle root is built from the columns and config; the channel mixes that root afterward. The source check correctly distinguishes raw `.s31` `source_text_sha256` from normalized `program_sha256`.

The focused [acceptance test](../../../../../src/frontends/s31/tests/acceptance/compiler_correspondence/public_main_root_binding.py) passed in the root worktree. I separately invoked the retained native prover on the saved `functional_square4` package, parsed the row export and root diagnostic, and manually decoded the first two commitment roots from the saved 54,831-byte proof. All 6,144 serialized main words hash to `3181458839c78d755d55bf7e80e9e43eed0d1f6354258ac18f82e5b92fcf42c3`, matching the diagnostic. The proof's main root and diagnostic both equal `1e60396f3638d2bd504893191347ff2688f69eec6e9588eaa05ca40a9f580e8a`; the proof's preprocessed root equals the sealed key. The honest native verifier accepted the proof. A one-byte main-root mutation was rejected at `InvalidInteractionNonce`, as expected because the main root enters the transcript before that nonce.

**What remains open:** both diagnostics derive their values from the same native `writeBase` implementation. The byte digest links the separately serialized row export to the recommitted columns under SHA-256 collision resistance, and the root matches this accepted proof under the PCS commitment implementation. It does not show that every arbitrary opening is an evaluation of those rows, prove source-to-AIR semantics for all programs, or discharge PCS/FRI/LogUp soundness. A next stronger check would replay selected query authentication paths against the decoded proof root and identified base evaluation columns, then formalize the compiler and verifier correspondence assumptions explicitly.

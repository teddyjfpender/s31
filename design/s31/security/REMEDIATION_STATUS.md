# S31 soundness remediation status

This is the implementation team's current status against the independent
[soundness review](INDEPENDENT_SOUNDNESS_REVIEW_2026-10-10.md). It does not amend
the review's original findings or claim an independent re-audit.

| Finding | Current implementation and evidence | Release gap |
| --- | --- | --- |
| S31-SEC-01: untrusted package executable | `s31 verify-pinned` copies the package to a private temporary directory, checks externally supplied source, key, prover, verifier, and (for text packages) text-source SHA-256 values, then executes that checked snapshot for base-proof verification. The focused admission tests and native record-selection acceptance exercise this path. | The pins need a trusted distribution channel; copying is not an execution sandbox. Recursive/fold verification still needs an independently trusted package or installed verifier. No signed release exists. |
| S31-SEC-02: public ABI sidecar | `verify_package` derives the ABI from the sealed source and rejects a forged sidecar; the adversarial package control records this rejection. | Repeat the control in release CI on supported package profiles. |
| S31-SEC-03: private endpoint exposure | The private boundary removes endpoints from the public statement but writes them to committed bridge rows. The documentation says this explicitly. | Blinding and a privacy analysis are required before promising witness confidentiality. |
| S31-SEC-04: general chip boundary | A source-derived bounded 1–8 call plan, typed component manifest, compiled endpoints and live AIR/PCS preflight feed the experimental V4 `S31MNY04` proof envelope and dedicated source-pinned verifier. Native proofs pass for every call count 1–8; the 2–8 matrix rejects each changed claimed sum. The fixed [mixed N=3 profile](../language/MIXED_NATIVE_N3_PROFILE.md) proves circuit/pair/pair/many in one STARK. The mixed manifest now recomputes chip and bridge binding digests from the exact compiled endpoint roster and checks component tree geometry; coherently resealed stale endpoint bindings reject. Fifteen sampled queried-value mutations and four Merkle authentication-path mutations across all four commitment trees reject through the native proof-byte verifier. The [independent N=3 review](INDEPENDENT_REVIEW_MIXED_N3_2026-10-11.md) and [private-manifest review](INDEPENDENT_REVIEW_PRIVATE_MANIFEST_ENDPOINT_JOIN_2026-10-12.md) record their narrower conclusions. | Arbitrary mixed rosters, full AIR/lookup/PCS soundness and source-to-verifier correspondence remain open. The in-process engine adapters alone are not authenticated S31 proof-byte APIs. Committed endpoint columns do not promise witness confidentiality. |
| S31-SEC-05: compiler correspondence | Lean checks bounded source/SSA and direct-gate input/output AIR-cell bridges. The selected direct Gate model relates all 11 residuals at arbitrary lifted rows and the previous-row mask order to source-bound bytecode outputs. A conditional OODS theorem relates 40 sampled values to finite circle-polynomial evaluations under explicit commitment binding. The [direct-free full alias model](INDEPENDENT_REVIEW_ALIAS_FULL_MODELED_DIRECT_FREE_2026-10-12.md) checks source/normalized/canonical bytes, constructs a 512-row modeled trace, and derives fixed cells, arithmetic roots, output and input binding without a direct-spelling premise. A [four-case native regression](../../../src/frontends/s31/tests/acceptance/compiler_correspondence/four_case_fixed_root_join.py) recommits 4,096 fixed cells per source to the same root decoded from each accepted proof, and rejects 24 fixed-column changes and four altered proof-root bytes. | Full installed Zig/bytecode refinement, native circle-basis and degree refinement, arbitrary proof-committed column authentication, cryptographic PCS/FRI/transcript soundness, other components, and a whole-program parser-to-verifier theorem remain open. The Lean model constructs its trace and takes external event addresses as input; it does not authenticate a native proof opening. |

The [profile soundness contract](PROFILE_SOUNDNESS.md) and
[functional v0.1.0 release contract](../language/FUNCTIONAL_V01.md) remain the
release gates. A passing test establishes only its stated profile and control;
it does not establish STARK soundness or source-language correctness for every
program.

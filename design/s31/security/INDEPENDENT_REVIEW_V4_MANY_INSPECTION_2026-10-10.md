## Findings, in release priority order

1. **P1 — Live AIR and PCS preflight is missing.** [`compareManyRoster`](../../../src/frontends/s31/runtime/bounded_compiled_binding.zig) (lines 287–314) checks the generated prefix-sum count, trace log, spans, constraints, and offsets against a planned roster. It does not compare the chip and bridge entries with instantiated V4 verifier component handles; in particular, it does not check their actual evaluation-degree bounds, relation dependencies, preprocessed indices, component program identity, or composition/PCS geometry. [`fromPlan`](../../../src/frontends/s31/runtime/bounded_component_manifest.zig) (lines 197–307) fills these fields from static pair-template formulas. The circuit entry is stronger because `inspectMany` obtains it from the rebound direct Gate AIR (bounded binding lines 194–226), but the other entries remain proposed geometry. Construct source-derived native handles first, compare **every** manifest field with their live component API, and derive tree logs, composition masks, FRI settings, proof-byte preflight, and claimed-sum order from that same roster before parsing proof bytes. Keep inspection results out of verifier admission until this holds.

2. **P1 before native proving — Witness-mode fixed columns are not compared.** [`checkWitnessTopology`](../../../src/frontends/s31/runtime/bounded_compiled_binding.zig) (lines 100–138) checks literal source digest, canonical call parameters, endpoint addresses, variable count, and row count. It does not compare the witness-mode fixed preprocessed columns or Merkle root with the value-free source inspection. The current compiler appears deterministic in these paths, so this is a latent mode-consistency gap, not a demonstrated exploit. Recompute the many-boundary preprocessed columns from the witness circuit and compare their exact values or root with the source-derived inspection before using that witness to prove.

3. **P2 — Per-bridge program identity omits its endpoint parameters.** [`nativeProgramDigest`](../../../src/frontends/s31/runtime/bounded_component_manifest.zig) (lines 427–443) includes the call ID, source node IDs, rounds, constant, and template source, but not the bridge's eight endpoint addresses. V3's native bridge binding explicitly includes those addresses ([`component_manifest.zig`](../../../src/frontends/s31/runtime/component_manifest.zig), lines 563–568). The **whole** V4 manifest digest does bind attached endpoints (bounded manifest lines 342–353), so this is no whole-manifest collision today. Once the per-component hash represents an executable bridge handle, include its source-derived input and output addresses, along with any other handle parameter, in that hash.

4. **P3 — Documented manifest and public-statement contract exceeds the current artifact.** The [V4 design](../language/BOUNDED_MULTI_CALL_BOUNDARY.md) says the manifest includes individual fixed-column value digests and an explicit native AIR version. The current [`Manifest` and `Source`](../../../src/frontends/s31/runtime/bounded_component_manifest.zig) (lines 29–34, 105–123) carry a preprocessed root and a native kind plus digest, but neither individual fixed-column digests nor a version field. A root is enough for cryptographic binding if its construction is fixed, yet individual digests aid audit and an explicit version prevents ambiguity at the component boundary. Add these fields when defining the admitted V4 key, or narrow the design text. Also specify whether the transcript mixes eight reserved public words with canonical zero padding or a length-delimited declared prefix for programs publishing fewer than eight words; the current [`TranscriptOrder`](../../../deps/stwo-zig/src/integrations/circuit_cpu/private_many_boundary.zig) (lines 245–290) is a proposed sequence only.

## Checks that held in the inspected source

Admission restricts source calls to live canonical repeats and permits a repeat input only from a private input or an earlier repeat ([`bounded_call_admission.zig`](../../../src/frontends/s31/language/bounded_call_admission.zig), lines 58–153). `inspectMany` derives endpoint addresses by compiling the source, then calculates the many-boundary preprocessed root from the resulting circuit; `matchesManyInspection` recompiles independently of candidate metadata (bounded binding lines 170–267). The engine's [`ManyBoundary`](../../../deps/stwo-zig/src/frontends/circuit/common/direct_arithmetic.zig) validates unique producers and adds one checked Gate multiplicity for **each endpoint occurrence**, including repeated addresses (lines 66–81, 193–199). The proposed V4 transcript phase order matches the existing V3 pair order, but no V4 native path enforces it. The [design](../language/BOUNDED_MULTI_CALL_BOUNDARY.md) correctly states that `private` is public-ABI visibility, not endpoint confidentiality.

# Independent review: native proof controls (2026-10-12)

**Scope:** `d240ddd` (mixed proof Merkle path mutations) and `8018355` (four public direct-Gate fixed-root joins), read against the checked-out Stwo verifier. These are finite regression tests, not a proof of PCS, FRI, or arbitrary compiler correspondence.

## Mixed private proof

The test first accepts an unchanged, source-pinned three-call proof. It decodes the postcard body at the same envelope length reconstructed by `general_package.headerLen(7)`, then changes one opened M31 value in the fixed tree and the first main and interaction column of each of seven native slots. The new four controls instead flip one byte of the first `hash_witness` sibling in each of the fixed, main, interaction, and quotient tree decommitments. Each changed proof retains the original envelope and commitment roots, passes the production structural preflight, and must fail `general_package.verifyEmbedded` at `RootMismatch`. The focused runner requires the PCS diagnostic's exact tree order: `0`, seven `1`s, seven `2`s, then `0,1,2,3`; a wrong tree, different error log, or missing rejection fails the test. In Stwo, this diagnostic surrounds that tree's `tree.verify` call, whose final step compares its reconstructed Merkle root against the previously committed root. Thus the path controls reach the Merkle verifier rather than merely failing envelope or shape parsing.

The proof body is deserialized and reserialized without an explicit pristine round-trip byte-equality assertion. Equal total length and changed bytes are checked, but the test does not assert that exactly one serialized byte changes. The same postcard serializer produced the original proof, and the ordered per-tree `RootMismatch` makes an unrelated failure unlikely; an exact byte-diff check would make the negative-control claim sharper. Only one sibling and one opened value per sampled column are exercised. The test does not authenticate unopened rows independently or establish the cryptographic assumptions in the PCS.

## Four public fixed roots

For each selected one-, eight-, 15-, and 16-gate source, `native_case` builds a fresh source-bound package, verifies the package/key and the complete native fixed/main diagnostic against the source-derived Python schedule and pinned digest, proves once, and requires its generated verifier to accept the exact proof/statement/key. The new script recommits all 4,096 canonical fixed words using `public_fixed_commitment.rootFromWords`, the production column preparation and Merkle commitment path. It requires equality with the sealed key, fresh topology, and decoded accepted proof fixed root.

The proof offset is correct: `proof_roots` returns the first byte of the main root as `main_offset`, so `main_offset - 32` addresses the first byte of the fixed root. The script changes only that proof byte and requires the generated verifier's exact `InvalidPreprocessedRoot` error. The native verifier parses the proof and compares commitment root zero to the sealed key before PCS verification. The three cell mutations and address-column swap are recommitted and required to produce different roots; they are **root-sensitivity checks**, not forged-proof verifier rejections. Noncanonical and short-column inputs must fail the native recommit command. All six controls per case are therefore distinct from the one proof-byte verifier rejection per case.

The checked-in fixture is a pin, not the only oracle: fresh source/package/export/proof work and the independent native recommit occur before the equality claim. The host schedule model is shared with package correspondence, so it is independent of the Zig emitter but not a second independent Python specification. Honest prover, exported rows, and generated verifier still share implementation assumptions; matching roots for four public programs does not show that arbitrary accepted openings equal a full displayed trace. These checks do not run for private direct-Gate row exports, which are deliberately unavailable.

**Verdict:** no blocker found within the stated finite regression scope. The remaining proof obligation is general accepted-proof-to-source/trace correspondence and PCS/FRI soundness; this review does not upgrade those to closed.

## Finding: the exporter rereads an unpinned topology

**P2 for audit-artifact provenance; no native verifier forgery shown.** [`render_bridge`](../../../scripts/export_s31_direct_gate_bridge.py) calls `check_package(package)` at line 159, then rereads `gate-topology.json` at line 168. The validator has checked the first read's complete rows, columns, manifest hashes and package artifact digest ([`correspondence.py`](../../../src/frontends/s31/python/package/correspondence.py), lines 309–417, 531–644), and returns `gate_topology_sha256`. The exporter does not compare the second read with that digest. Source and normalized relation bytes *are* reread with explicit digest comparisons (exporter lines 160–167). A package file replaced between validation and export could therefore supply the Lean fixture's cell arrays without undergoing the complete topology replay for that version. The Lean equality check would still reject a changed source cell that disagrees with its expected value, but unrelated rows could be different while the artifact is described as package-checked. Parse a single captured topology byte buffer and check its SHA-256 against `checked["gate_topology_sha256"]`, or pass the already validated topology out of the checker.

## Precise formal boundary

**P1 before claiming full compiler or proof-system correspondence; not an unsound theorem.** `checkRelation` computes the expected *whole* canonical normalized JSON byte sequence from the parsed `.s31` bytes and requires exact equality ([`SSANormalizedBytes.lean`](../../../formal/s31/S31/Gadgets/Functional/SSANormalizedBytes.lean), lines 33–49). The new cell model covers all eight fixed-column fields **at each source operation's grouped row**, and computes selector, source addresses and output use count from the same certificate (column cells lines 25–66). The concrete fixture checks two source rows, 502 and 503, and rejects changed selector, address, sampled row and multiplicity cells ([`GeneratedDirectGateBridge.lean`](../../../formal/s31/S31/Gadgets/Functional/GeneratedDirectGateBridge.lean), lines 154–220). I found no inconsistency in that stated local equality.

The general `checked_air_cells_sound` theorem (column cells lines 72–79) takes `observedCells = expectedCells ...` as a premise and pairs that premise with source-byte semantic equality. It does not derive cells from a committed proof, establish the whole 512-row topology, or connect AIR operand values to the named SSA wires. The generated `checked_instance_air_claim` additionally assumes `AcceptsTrace`, whose row operands are already the prior modeled values (generated bridge lines 275–290; [`SSAAirRows.lean`](../../../formal/s31/S31/Gadgets/Functional/SSAAirRows.lean), lines 25–33, 77–86). These assumptions are explicit; they must not be counted as a native verifier soundness theorem. The [compiler correspondence guide](../language/COMPILER_CORRESPONDENCE.md) correctly lists native Gate lookup, committed-column, Python/Zig parser, and PCS correspondence as open.

The last result's `+4` use count is an expected multiplicity in `sourceUses` (column cells lines 37–45); Lean does **not** derive the existence or correctness of the four public-unpack mask gates. The Python package checker checks those rows ([`correspondence.py`](../../../src/frontends/s31/python/package/correspondence.py), lines 473–488). Likewise, `totalAddRows` is supplied by the checker, and the eight columns' AIR selection order `[0,2,3,1,4,5,6,7]` and official AIR bundle identity are checked outside this Lean cell relation (checker lines 576–604). The documentation should continue to attribute these controls to the Python package gate, not to the Lean theorem. That package gate still requires an external trust root for its files and executable.

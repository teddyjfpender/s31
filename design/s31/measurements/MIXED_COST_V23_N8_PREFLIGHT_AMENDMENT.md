# V23 preflight amendment before native observation

The first V23 preregistration, isolated commit `726085a` and PR commit `9143529`, used protocol SHA-256 `ccca586fa78c35ba53be4f2fdb819c8f67a55794c574c5f0f7495f4ce65204c1`. Its first runner invocation stopped in the host-idle preflight before creating the `O_EXCL` attempt marker, output directory, package, proof, or timing record. The macOS `ps` `comm` field included spaces (for example, `Core Audio Driver`), so a whitespace parser treated part of the process name as the CPU field. The snapshot also showed ambient Kandji and Codex daemon CPU readings of about 10% and 17%. This was a tooling/preflight failure, not a native build or cost-model observation.

Before any native attempt, the parser was changed to collect `pid,%cpu,comm` with CPU as the second whitespace field, and the threshold for unrelated processes was set to 25% of one CPU. Compiler work (`lean`, `leanchecker`, `lake`, `zig`, `zig2`) is rejected at any CPU reading. Two snapshots one second apart remain required. The attempted invocation's absence of both marker and output directory was checked after the failure. The amended protocol and its tool hashes are frozen in the following commit and must be pushed before the one native attempt. The source, claims, cost predictions, geometry, gates, and pinned compiler base are unchanged.

After the amended preregistration was pushed, a second preflight invocation also stopped before marker, output directory, package, proof, or timing record because `corespotlightd` read 176.9% CPU. Its CPU reading soon fell; a later preflight under the *same amended protocol* passed and created the single native attempt marker. Neither preflight rejection is a model observation.
